Role

config owns the user's intended Git decision style. It is the only persistent owner for targets, roles, filters, policy enablement, report budgets, workflow preferences, and suggested command templates.

Config Data

field groupmeaningcurrent or roadmap
targetsNamed worktree or bundle targets such as release and runner.current
rolesAllowed operations, cleanliness requirements, filters, protect patterns, delete policy.current
policiesEnabled/disabled policy code patterns and severity defaults.current
reportmax_lines, changed_preview_limit, and default_detail for bounded report output.current
command_styledirty_target_strategy, commit_message_template, and preferred_remote.current
command allow/denyallow_commands and deny_commands constrain suggested commands in report.commands.current

Command Style

Suggested commands are config-owned preferences. The advisor transform reads command_style and generates report.commands and report.workflow; it does not execute those commands.

{
  "report": {
    "max_lines": 80,
    "changed_preview_limit": 12,
    "default_detail": "compact"
  },
  "command_style": {
    "dirty_target_strategy": "ask|stash|commit",
    "commit_message_template": "prepare {target} sync",
    "preferred_remote": "origin",
    "allow_commands": ["git status", "git diff", "git add", "git commit", "git stash"],
    "deny_commands": ["git reset --hard", "git clean", "git push --force"]
  }
}

Boundary

Config does not read Git and does not execute commands. It only defines legal preferences and constraints. Git facts are transform inputs; execution evidence belongs in report.
