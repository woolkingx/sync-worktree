Purpose

sync-worktree gives an AI agent a short, usable Git decision report before it acts. It exists because agents can otherwise treat a bare repo, source worktree, release worktree, and runner worktree as one flat directory and then run the wrong Git operation in the wrong place.

The original pressure came from Claude-style Git drift: branch confusion, dirty target edits, accidental worktree mutation, and unclear release/runner boundaries. Codex is steadier, but bounded reports still matter because they reduce context size and make the next safe action explicit.

Decision Support First

The tool does not start from "copy all files" or "dump full repository context". It starts from "what short report helps the AI choose the next safe Git action?" A sync operation is only one possible workflow after report generation.

project root
  .bare/ or .git/
  source worktree or bundle
  target worktree
  rule.config.json
  setting.config.json

AI operation
  config -> git facts -> bounded report -> decide -> apply or abort

sync decision path
  source data -> target role -> candidate files -> actions -> policy -> apply

Invariant

A target may be modified only after a report has made the status, risk, recommendation, commands, and workflow explicit. The report is the AI-facing decision surface; full Git traces are supporting evidence, not the default context.
