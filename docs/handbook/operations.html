Command Semantics

commandcurrent meaningboundary
inspectExport bounded report for one target or all targets. Use --full for the full context contract.Primary read-only decision support surface.
doctorCheck whether the current repository can safely use sync-worktree.Read-only environment and configuration diagnosis.
explain <target>Explain which config, facts, and policies produced the current report decision.Read-only reasoning projection for agents.
check <target>Build a report for the sync workflow without writing target files. Use --json --full for trace data.Read-only report generation.
sync <target>Same as check unless --apply is present. Use --json --full for trace data.Read-only by default.
sync --target <target>Legacy compatibility alias for older agent command templates. Emits a deprecation warning and normalizes to sync <target>.Ingress compatibility only; not the canonical operation shape.
sync <target> --applyValidate, create backup branch when configured, copy/modify/delete, run git add -A, persist sync state.Direct write boundary for the sync decision path.
apply --from-decisionExecute an AI decision after the report and optional context hash make the action explicit.Decision execution boundary.
target add/removeMutate target bindings in rule config.Config write boundary.
config show/schemaProject effective config and reference config shape.Read-only config projection.

Execution Gate

inspect/apply:
  inspect current topology and target state
  build bounded report
  AI emits decision
  apply verifies optional full-context hash when requested
  dry-run returns report evidence
  dispatches to safe operation or abort

check/sync:
  detect topology
  load config
  compute transform-local plan
  validate config-driven checks
  build report
  if no --apply:
    report only
  if --json --full:
    report plus trace
  if --apply:
    execute validated plan
    persist sync-worktree.state.json

Agent Preflight

doctor:
  detect topology
  load config
  inspect configured targets and bundle source
  return compact report-style diagnosis

explain:
  build the same report as check
  attach config/policy/fact edges
  return why the status, reason, commands, and workflow were chosen

doctor and explain are for agents that need a quick orientation before editing or applying. They must stay read-only and bounded by default.

Full Trace Flags

python3 sync_worktree.py check runner --json
python3 sync_worktree.py check runner --json --full
python3 sync_worktree.py sync runner --json --full
python3 sync_worktree.py inspect --target runner
python3 sync_worktree.py inspect --target runner --full

Default output is the bounded report. Full context and file-list trace modes are opt-in so AI agents do not need to parse thousands of lines before making a decision.

--target remains canonical for inspect. For sync, the target is positional; the legacy flag exists only to keep stale agent templates from hard-failing before they can be corrected.

Known Semantic Problem

sync is currently ambiguous because it validates by default and writes only with --apply. The command is safe, but the name makes operation intent unclear. The report must always state whether the next workflow is review, clean target, rerun check, or apply.
