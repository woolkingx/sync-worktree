Policy Position

Policy is a config-driven checker submodule. It does not own durable data. It reads config and current transform facts, then projects risk/status/evidence into the report owner.

Implemented Policies

codesubmodulereport projection
POL-TOP-001policy/topology/role.pyBlocked risk when operation is not allowed by target role.
POL-TOP-002policy/topology/cleanliness.pyBlocked risk plus review/clean workflow when target worktree is dirty.
POL-CON-001policy/content/forbidden_paths.pyBlocked risk plus filter/config recommendation when forbidden paths enter candidates.

Enablement

RuleConfig.policies enables or disables policy codes by exact code or wildcard. Target role overrides may replace enabled lists or add disabled policies. Policy enablement is config data; policy result is report data.

{
  "policies": {
    "enabled": ["POL-TOP-*", "POL-CON-*", "POL-SEC-*"],
    "disabled": []
  }
}

Boundary Rule

Do not add a new policy schema or durable policy state unless it is truly config. Policy code is transform logic from config + facts to report.risks, report.status, report.recommendation, and report.workflow.
